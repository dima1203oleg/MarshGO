# План підключення транспортних операторів MARSHGO

Стан на 8 жовтня 2026. Реєстрація провайдера в каталозі сама по собі не означає, що пошук, замовлення або бронювання працює. Для кожного API потрібні контракт, опис авторизації, sandbox та окремі перевірки ціни й бронювання.

## Уже підключені відкриті джерела

| Клас | Оператори/джерела в каталозі | Що реально працює | Наступне |
|---|---|---|---|
| Міські та приміські автобуси, трамваї, тролейбуси, метро, поїзди | Увімкнені відкриті GTFS-feeds із `server/mobility/ukraineCatalog.ts` | Карта показує шари мережі; пошук поїздок знаходить прямі рейси із календаря GTFS, коли обидві точки в зоні покриття | Звірити опубліковану свіжість кожного feed, підключити GTFS-RT до результатів і мультимодальний routing |
| Live-позиції громадського транспорту | Увімкнені GTFS-RT та JSON feeds | Позиції доступні для відповідних шарів карти | Окремо узгодити vehicle trip updates/затримки з розкладом |
| Е-самокати | 3electra, Київ, GBFS | Read-only доступність і місця на карті/поруч | Запросити операторський API для тарифу, старту/завершення оренди та оплати |
| Інші велосипеди/самокати/каршеринг | Будь-який доступний операторський GBFS feed | Можна під'єднати доступність стандартним GBFS-адаптером | Підтвердити наявність feed у потрібних містах; бронювання вимагає окремого API |
| Попутки | MARSHGO | Пошук, ціна, місця та внутрішній сценарій бронювання | Розширювати власне покриття водіїв |

GTFS описує розклад, а GBFS — публічну read-only доступність спільного транспорту. Жоден із цих стандартів самостійно не надає продаж квитків чи замовлення поїздки. [Специфікація GBFS](https://github.com/MobilityData/gbfs) прямо обмежує стандарт актуальними read-only даними.

## Кандидати на партнерські інтеграції

| Пріоритет | Оператор/категорія | Потрібний доступ від власника MARSHGO | Що додасться після доступу |
|---|---|---|---|
| P0 | Uber rides | Зареєстрований застосунок; Uber OAuth; згода кожного пасажира; схвалення привілейованих ride-request scopes. Токен зберігати на сервері/у secure storage | Перевірка продуктів/оцінки та передача замовлення у Uber, якщо доступ схвалений |
| P0 | Uklon та Bolt rides | Письмове підтвердження доступної партнерської програми, API документація, sandbox, ключі та правила для України | Ціна/ETA, deep link або створення замовлення — лише за дозволеним контрактом API |
| P0 | Укрзалізниця | Партнерський доступ до пошуку місць, тарифів та бронювання/продажу | Реальна наявність місць і квитки; відкритий/дзеркальний GTFS лишається тільки розкладом |
| P1 | Міжміські автобуси: INFOBUS, busfor/оператори | API/affiliate контракт, документація, sandbox і комісійні/бронювальні правила | Пошук тарифів та бронювання там, де це дозволяє конкретний партнер |
| P1 | Авіаквитки: Amadeus Self-Service або акредитований агрегатор | API-акаунт, production approval, умови продажу/виписки квитків, оплата та підтримка змін | Пошук і котирування рейсів; booking увімкнути тільки після підтвердження повного ticketing workflow |
| P1 | Оренда авто, каршеринг, мопеди та e-bike | API/affiliate доступ кожного оператора, city coverage, обмеження геолокації, тарифи та бронювання | Наявність і ціни; GBFS інтегрується окремо тільки для видимості доступних одиниць |
| P2 | Поромні лінії | Операторський розклад/feed/API, валюта й правила продажу | Розклад або продаж після отримання джерела; відкритих українських фідів у поточному каталозі немає |

Uber вимагає авторизацію користувача для ride request та схвалення потрібних привілейованих доступів; backend-only токен не замінює згоду пасажира. [Uber Ride Requests](https://developer.uber.com/docs/riders/ride-requests/introduction), [OAuth і scopes](https://developer.uber.com/docs/riders/ride-requests/tutorials/api/best-practices). Публічний Transitous API не підходить як production залежність комерційного MARSHGO: його правила допускають лише некомерційні open-source застосунки та просять узгоджувати ресурсомісткі запити. [Transitous API usage](https://transitous.org/api/).

## Що потрібно передати для кожного оператора

1. Назву оператора, територію/міста й контакт відповідальної особи.
2. Публічну API документацію та підтвердження права на комерційне використання.
3. Sandbox base URL, приклади запиту/відповіді та тестові облікові дані.
4. Перелік функцій: пошук, quote, availability, booking, cancel/refund, live updates.
5. Технічне ім'я секрету в Secret Manager/CI; секретні значення не передавати у чат, Git або `.env` репозиторію.
6. Правила attribution, rate limits, retention, service-level expectations і контакти підтримки.

Для наступного кроку достатньо надіслати назви схвалених операторів та посилання на їх API-документацію; ключі залишити у секретному сховищі.
