## Summary

The repository started as a React/Vite PWA prototype. The production build uses an Express/PostgreSQL API for OTP sessions, offers, bookings, garage records, passenger demand/proposals, booking-participant chat, user-ID blocks, foreground navigation sessions and opt-in route candidate matching. Mutually confirmed navigation candidates can open in the driver's existing explicit demand proposal flow. The iOS Capacitor target builds and launches in CoreSimulator. Configurable geocoder/routing adapters exist, but no providers are configured, so real place selection and navigation cannot be exercised end-to-end. Production SMS, photo storage, hosting, staging, multi-instance realtime delivery, interactive device acceptance, and release operations remain incomplete.

## Production acceptance boundary

The two-phone acceptance criterion is not met end to end: real SMS is unconfigured, staging is absent, the production PWA has only search/booking/passenger history, and no two physical devices were tested. The API transaction itself passed a local parallel last-seat integration test. Do not describe the app as production-ready until two independently authenticated devices complete the full flow against staging and the remaining checklist passes.
