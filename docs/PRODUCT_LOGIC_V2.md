# MARSHGO UX/Logic v2 — модель продукту і статус реалізації

Принципи (обов'язкові):
1. Роль визначається **дією** у конкретному сценарії, а не профілем. Немає глобального перемикача «Я водій / Я пасажир», немає окремих Home для водія й пасажира.
2. Водій не створює поїздку щоразу, коли просто їде: «Почати навігацію» → MARSHGO сам шукає попутників уздовж маршруту.
3. Запланована поїздка — об'єкт, який можна редагувати; зміни проходять повторний matching і, за потреби, підтвердження пасажирів.
4. Після домовленості водій і пасажир переходять у Live Pickup Mode.

Головний екран: **Почати навігацію** · **Шукати поїздку** · **Запланувати поїздку**. Карта на головній відсутня.

## Статус (2026-10-08)

| Вимога ТЗ | Статус |
|---|---|
| Головна з трьома кнопками, без карти/списків/перемикача ролі | **Є** (`HomeHero`) |
| «Почати навігацію» без пункту призначення, карта + поле «Куди їдемо?» зверху | **Є** (`POST /navigation/sessions` з лише origin, `PUT …/destination`) |
| Навігація для всіх користувачів; matching лише з верифікованим авто | **Є** (ролі знято з lifecycle-ендпоїнтів; вибір кандидатів лишається дією водія) |
| Passive matching за замовчуванням для водія з авто; підказка «Додати автомобіль» | **Є** (запам'ятовується перемикач у панелі) |
| «Шукати поїздку» (Звідки/Куди/Коли/Пасажири, «Моя локація») | **Є** (вкладка «Пошук») |
| «Запланувати поїздку» → «Як ви їдете?» (авто / хочу поїхати) | **Є** (екран `/trips/plan`, далі наявні форми оголошення й запиту) |
| Коридор за напрямком руху без пункту призначення | **Немає.** Matching стартує після вибору пункту; потрібен окремий алгоритм гіпотези маршруту |
| Проміжні точки запланованої поїздки у matching (Trip/TripStop) | **Немає** (є запис stop-ів у навігаційних waypoints після підтвердження пасажира) |
| Редагування запланованої поїздки + TripChange/TripChangeApproval, повторний matching | **Немає** |
| Версії ціни (Proposed vs Confirmed price), політика зміни ціни/часу | **Немає** (ціна фіксується в booking) |
| Scheduled matching (пошук під майбутню поїздку) | **Частково:** заявки пасажирів і пропозиції водіїв є; автоматичного пошуку кандидатів для запланованої поїздки немає |
| Live Pickup Mode (взаємні позиції, 500/200/100/50 м, «Я на місці») | **Частково:** ephemeral rendezvous (позиції 5 хв, статуси approaching/arrived/delayed). Без руху в реальному часі й геозонної перевірки посадки |
| Realtime-події з розділу 45 | **Частково:** `navigation.match.*`, `navigation.route-updated`, повідомлення чату. Решти (`trip.*`, `pickup.*`) немає |
| iOS: native background location, push, lock screen | **Немає.** Лише foreground GPS; не обіцяти фонову навігацію |
| Голосові підказки, режим «водій за кермом» | **Немає** |

## Порядок наступних етапів
1. Trip/TripStop/TripSchedule + редагування, TripChange з підтвердженням пасажирів, версії ціни, re-matching.
2. Live Pickup: realtime-події `pickup.*`, геозони, кнопки водія/пасажира.
3. Scheduled matching для запланованих поїздок.
4. iOS native background location + push, перевірка на реальному iPhone.
5. Режим «без пункту призначення»: коридор за напрямком руху.
