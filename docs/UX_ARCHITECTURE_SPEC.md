# MARSHGO — ГЛИБОКИЙ UX/UI АУДИТ ТА ВИПРАВЛЕННЯ МАРШРУТИЗАЦІЇ

**ВАЖЛИВО:**
Не робити поверхневий rename текстів. 
Потрібно спочатку проаналізувати фактичний код проекту та побудувати правильну карту:
`UI-кнопка → дія → route/view → наступний flow → результат`.
Після аналізу виправити саму маршрутизацію, щоб однакова дія всюди відкривала один і той самий flow.

## 1. ФАКТИЧНИЙ СТАН, ЯКИЙ ПОТРІБНО ВИПРАВИТИ

**Завдання:** 
1. Прибрати різнобій у назвах («Пропоную попутку», «Створити попутку», «driver_offer_new» і «Запланувати поїздку»).
2. Заборонити кнопці "Шукаю поїздку" відкривати одразу `DemandNewView`. Вона має вести на `SearchView`.
3. «Заявки» у BottomNav означає різні речі для пасажира і водія.
4. Чітко розділити: поїздку водія, заявку пасажира, пошук поїздок, пошук пасажирів, навігацію.

## 2. ГОЛОВНА СТОРІНКА (3 ОСНОВНІ ДІЇ)

### 1. «Почати навігацію» (ВОДІЙ)
- **Flow**: `Почати навігацію` → `NavigationView` → вказати маршрут → запуск `NavigationSession`.
- Водій може просто їхати своїм маршрутом, а MARSHGO пасивно знаходить заявки пасажирів уздовж маршруту. 
- НЕ вимагати попереднього створення поїздки.

### 2. «Шукаю поїздку» (ПАСАЖИР)
- **Flow**: `Шукаю поїздку` → `SearchView`.
- **Основна кнопка**: `Знайти поїздки` (список DriverOffer / TransportOffer).
- Якщо нічого немає: `Поїздок за вашим маршрутом не знайдено` → `Створити заявку` → `DemandNewView` → `Опублікувати заявку`.

### 3. «Запланувати поїздку» (ВОДІЙ)
- **Flow**: `Запланувати поїздку` → `DriverOfferNewView` → параметри маршруту та ціни → `Опублікувати поїздку`.
- Після цього поїздка стає доступною через `SearchView` пасажира.

## 3. МЕНЮ «+» (ACTION DRAWER)
Кнопка «+» повинна бути універсальним меню швидких дій і дублювати головну логіку:

1. 🚶 **Шукаю поїздку** → веде в `SearchView` (ЯК І ГОЛОВНА КНОПКА).
2. 🚗 **Запланувати поїздку** → веде в `DriverOfferNewView`.
3. 👤 **Знайти пасажира** → веде в `DriverRequestsView` (перегляд відкритих заявок).
4. 🧭 **Почати навігацію** → веде в `NavigationView`.

## 4. ТЕРМІНОЛОГІЯ ТА СИМЕТРІЯ
**ПОЇЗДКА** створюється водієм.
**ЗАЯВКА** створюється пасажиром.
- Правильно: "Опублікувати поїздку", "Опублікувати заявку".
- Неправильно: "Водій опублікував заявку", "Пасажир опублікував поїздку".

## 5. ЗАБОРОНА ДУБЛЮВАННЯ ТА ВИМОГИ МАРШРУТИЗАЦІЇ
Одна дія = один route/view:
- `Шукаю поїздку` → `SearchView`
- `Запланувати поїздку` → `DriverOfferNewView`
- `Знайти пасажира` → `DriverRequestsView`
- `Почати навігацію` → `NavigationView`
- `Створити заявку` → `DemandNewView`

### Перевірка всіх flows після рефакторингу:
- Головна → Шукаю поїздку → SearchView.
- + → Шукаю поїздку → ТОЙ САМИЙ SearchView.
- SearchView → немає результатів → Створити заявку → DemandNewView.
- Головна → Запланувати поїздку → DriverOfferNewView.
- + → Знайти пасажира → DriverRequestsView.
- Головна → Почати навігацію → NavigationView.
- Перевірити mobile/desktop layout (зокрема iPhone 15/16 Pro Max).
