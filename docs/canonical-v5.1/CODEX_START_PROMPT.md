# Завдання для Codex: MARSHGO — єдина платформа, канонічна специфікація v5.1

Працюй як senior product architect, UX lead, full-stack tech lead та QA lead для **основного MARSHGO**. Прочитай ПОВНІСТЮ файл `MARSHGO_CANONICAL_TZ_v5_1.md`, вивчи всі п'ять скринів у `references/`, використовуй їх як візуальні референси, а не як готові API, підтверджені ціни чи маршрути.

Перевір актуальний код і всі гілки чотирьох репозиторіїв `dima1203oleg/MarshGO`, `MarshGO-Site`, `MarshGO-Server`, `MarshGO-iOS` (не MARSHGO 2). Не припускай, що попередні локальні зміни вже є на GitHub. Спочатку зроби код-аудит і матрицю реалізації/прогалин; окремо покажи статус кожного важливого API-провайдера та blocker. Звір контракти й статус реальних інтеграцій. Запропонуй PR-декомпозицію з залежностями й перевірками.

Потім реалізуй ПОЕТАПНО один спільний продукт: Home → Search → Multi-leg Journey → єдина карта → бронювання / квиток / поїздка → живий супровід пересадок → Driver Pure Drive → matching → повідомлення → профіль → admin. Не створюй дублюючих UI/моделей, не видумуй live транспортні дані. Пам'ятай: у водійській активній навігації немає глобального центрального плюса; нижня «губа» має CTA «Завершити навігацію» всередині розгорнутого стану; вторинні кнопки автоматично затихають, залишаючи видимими карту, маршрут, маневр, GPS-швидкість, достовірний знак обмеження та ETA.

Забезпечуй зворотну сумісність, атомарність бронювання, авторизацію, перевірку джерел і ліцензій, iOS capability detection, справжні маневри маршруту. Після кожного vertical slice: unit/integration/E2E + збірка + реальні скриншоти iPhone 15 Pro Max/desktop + звіт про те, що готове, неготове та заблоковане. Синхронізуй зміни між чотирма repo через окремі PR, не роби force-push чи публічного релізу без явного дозволу.

**Першою відповіддю дай аудит, матрицю прогалин, plan P0–P5, залежності і перший маленький PR. Не перескакуй прямо до косметичного редизайну, доки не звірив архітектуру й shared contracts.**
