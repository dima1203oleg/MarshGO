## P1 — перед пілотом

- Перенести й перевірити у Server відсутню поведінку пошуку попуток по проміжному коридору та `other_date` fallback.
- Узгодити єдине джерело користувацького UI у Site та довести збереження search state, lifecycle, чат, rescue і повернення з деталей на браузерному E2E.
- Провести перехресні API contract tests: поточний Site проти поточного Server, включно з невідомими цінами/даними, GPS freshness і помилками провайдерів.
- Окремо підтвердити OTP, push, оплату/комісії й booking/refund policies на staging. У коді наявність маршруту не дорівнює зовнішньому підтвердженню.
- Перенести з legacy активну CI/E2E та release orchestration у цільового власника, щоб основні CI не залежали від старого репозиторію.
- Створити PII/privacy retention, адміністрування й модераційний операційний runbook та перевірити права доступу.

## P2 — до повного комерційного запуску

- Навантажувальні тести з реальними профілями пошуку/бронювання, вимірювання p95 та ресурсів.
- Формалізовані SLA/SLO, алерти на свіжість фідів, помилки OTP/payment/booking, вичерпання пулів і відмови Redis.
- Юридичне підтвердження ліцензій, тарифів, обробки геолокації та договірних меж кожного data/booking provider.
- Механізм підтримки/спірних бронювань, фінансові reconciliation звіти, резервне відновлення й операційне чергування.

Production readiness залишається **не підтвердженою** до зняття P0-блокерів. Це не є погодженням на deployment або App Store publication.
