# Готовність MarshGO до архівування

Стан на 12.10.2026: **НЕ ГОТОВИЙ до архівування**.

## Причини

1. В історичному репозиторії досі є runtime-підключені backend можливості, відсутні або відмінні в MarshGO-Server. Підтверджені приклади: stop-arrival/ETA, частина vehicle cache/feed polling, пошук попутки по проміжному маршруту та пошук на інші дати.
2. Активний root CI є власником міжрепозиторних integration/E2E, release materializer та Compose build. Перенесення й перевірку цих сценаріїв у Server/Site/iOS не завершено.
3. Production Docker, backup/restore, release manifest і deployment orchestration лишаються в legacy tree; їх власника серед трьох репозиторіїв не визначено тестами.
4. Існують SQL migration collisions (`041`, `043`, `044`) і кількісна/схемна розбіжність. Upgrade rehearsal не пройдено.
5. iOS wrapper використовує Site SHA `1745822…`, а перевірена робоча Site гілка зараз на `570ea7b…`.
6. Усі коміти, гілки й теги ще не збережено та не перевірено через відновлюваний `git bundle`.
7. E2E rerun на момент звіту ще не завершив браузерні кроки.

## Що дозволено зробити до окремого підтвердження власника

- Продовжувати аудит, переносити код у цільові репозиторії за контрольованими forward-only комітами та повертатися за кожним repo-specific тестом.
- Підготувати `ARCHIVE_README.md`, `ARCHIVE_MANIFEST.md`, `MIGRATION_HISTORY.md` лише після фактичного завершення потрібних переносів.
- Створити й перевірити повну backup-копію гілок/тегів без секретів.
- Підготувати фінальну рекомендацію власнику.

## Що не виконано

Репозиторій не переведено в GitHub Archived, не видалявся, історію чи робочі refs не переписували. Поточний статус **NO-GO**: архівування втратило б активну відповідальність за CI/release та функціональні можливості.

Переглянути статус після виконання `03_MIGRATION_MATRIX.md`, усіх CI/E2E перенесених сценаріїв, migration rehearsal та відновлення bundle. Будь-яке фактичне GitHub archive потребуватиме окремого підтвердження власника.
