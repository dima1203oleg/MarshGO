# MARSHGO — план удосконалення (2026-10-08)

Аналіз: ядро (бронювання, переговори, навігація, підбір попутників, realtime, транспортні шари) працює й покрите тестами.
Найбільші прогалини з погляду користувача й ТЗ:

| # | Проблема | Наслідок |
|---|---|---|
| 1 | Опубліковану поїздку **неможливо змінити чи скасувати** (немає API й UI) | водій не може виправити ціну/час/місця; пасажири не дізнаються про зміни |
| 2 | Немає історії змін і підтвердження суттєвих змін пасажиром | конфлікти, мовчазне підвищення ціни |
| 3 | «Мої оголошення» показують сирий статус `published`, усі поїздки разом | погана читабельність |
| 4 | Нижня панель навігації довга, текстова | відволікає водія |
| 5 | Немає фото водія (окремо від фото авто) | вимога ТЗ |

## Етапи
1. **Керування поїздкою (бекенд):** `PATCH /offers/:id` (ціна, час відправлення, місця, авто), `POST /offers/:id/cancel`, `GET /offers/:id/changes`; таблиці `offer_changes` (історія) і `booking_change_approvals`.
   Політика: зниження ціни застосовується до підтверджених бронювань автоматично; підвищення ціни, зсув часу понад 30 хв або зміна авто потребують підтвердження кожного пасажира (`POST /booking-changes/:id/accept|reject`; відмова = безкоштовне скасування з поверненням місць). Місця не можна зменшити нижче вже заброньованих. Усе через транзакції, аудит і realtime-outbox → push.
2. **Керування поїздкою (UI):** «Редагувати» / «Скасувати поїздку» у «Мої оголошення», картка змін у бронюванні пасажира («Було → Стало», «Погодитися / Відмовитися»), людські статуси.
3. **Навігація:** компактна нижня панель (статус + перемикач підбору + завершення).
4. **Фото водія** (окремо від фото авто).
5. Тести: інтеграційні для кожного правила, аудит кнопок, compat, E2E.
